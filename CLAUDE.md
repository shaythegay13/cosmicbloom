# Cosmic Bloom — Project Context

## What this is
Unity 6 (6000.5.1f1) mobile farming game. Data-driven core loop: farm → rewild → unlock regions → progress through a 47-quest main chain across 4 acts. Pivoted from a finished web game ("Farm & Give," same repo under client/server/ios/android/tools) — that old code is reference only. Don't touch it or port from it directly.

## Architecture
- Namespace `CosmicBloom`, split by folder: Core, Data, Farming, Net, Save, Config, World, UI, Player.
- Everything dynamic (player, NPCs, animals, plots, UI) spawns at runtime from data via `GameBootstrap` — the scene only holds managers/camera/light/tilemap grids. Don't hand-place gameplay objects in the scene; add them to a spawner.
- `GameDatabase.LoadAll()` loads all 6 JSON files (regions/crops/npcs/quests/animals/tools) from `Assets/Resources/GameData/`. `.Region(id)` / `.Crop(id)` / `.Npc(id)` / `.Quest(id)` are the lookups.
- `FarmingSystem` owns till/plant/water/harvest + soil + day/night grow gating. Plots are keyed by `"x,y"` region-local cell coords in `FarmState.plots` with no coordinate-range restriction — the data model has always supported arbitrary positions.
- **Free-form plot placement (P3-Phase 17, 2026-07-21) — replaces the old fixed 256-cell lush-core grid; systems that reference the old model must be read through this.** Tapping any tillable ground cell tills it and creates a plot there; a plot exists only where one was tilled. `FarmGrid` no longer eagerly instantiates a `FarmPlot` per lush-core cell — it materialises a view **on demand**: for plots restored from the save on load, and for new ones the instant a cell is tilled (it subscribes to `FarmingSystem.OnAction` and spawns the view on any `"till"`, from any caller). ~1600 cells/region are never all instantiated. `FarmGrid.ForRegion(id)` is a static registry so `PlayerController`'s ground-tap path can reach the current region's grid; tapping bare tillable ground walks there and tills (already-tilled cells own a `FarmPlot` collider and route through the normal `IInteractable` tap path for plant/water/harvest). `RegionWorldBuilder.IsTillable(x,y)` = in-bounds AND not `ReservedTiles.IsReserved` (landmark footprints + the NPC social plaza — the only fixed structures; per-NPC mobile Home/Work stops are deliberately NOT reserved, see BUILD_LOG P3-Phase 17). Soil tier is a **quality modifier, not a placement gate**: `FarmingSystem.StartingSoilFor` seeds a freshly tilled cell by tier (lush 100 / mid 80 / wild 65) — everywhere is tillable, not everywhere equally good; the 65 floor sits above the `q_soil_secrets` "soil_above 60" poll so no quest's completability changed. `FarmingSystem.MaxPlotsPerFarm` (1000) matches `server/routes/game.js#validateSnapshot`'s cap so free-form tilling can't build an unsyncable save — a determined completionist hitting it in one region is a flagged DECISION (see BUILD_LOG), not a silent cap change. `ToolService.Perform` gates till AoE on `InBounds` + reserved (was `IsFarmable`); `IsFarmable` (tier-2 core) now only feeds decoration placement + tests.
- **Free-form placement UX feedback (P3-Phase 17 live-verify fixes, 2026-07-23)** — a real tap-driven end-to-end pass (not the test suite) surfaced five feedback gaps; all fixed in `Assets/Scripts/Farming/FarmPlot.cs` + two new small components. Soil tier is now visible, not just numeric: `FarmPlot.TilledColorFor(tier)` tints bare-tilled dirt lush/mid/wild differently. Sorting order is dynamic, not fixed: a plot is `BaseSortingOrder=5` (below the player=10) when empty/tilled, `CropSortingOrder=11` (above the player) the instant it holds a crop — a growing plant is no longer fully hidden by someone standing on the tile. `FarmActionEffects` gained a `PlantSpec` burst (was the only farm action with zero FX). `Farming.FarmActionPrompt` (world-space `TextMesh`, created once per player in `GameBootstrap`) follows the player and shows "Tap to till/plant/water/harvest" via `FarmGrid.ContextActionAt(worldPos)` — a small new query that, unlike `FarmingSystem.ActionFor`, checks `IsTillable` for bare ground so it doesn't mislabel a reserved tile. `FarmingSystem.OnReward` (x,y,coins,xp) is a new event fired alongside harvest's existing `OnAction`; `Farming.RewardPopup` (also world-space `TextMesh`) subscribes per-plot in `FarmPlot` and shows a rising "+Nc +Nxp" at the plot itself, additive to the HUD's counters. Both new popups/prompts are deliberately unparented fire-and-forget-style GameObjects (matching `FarmActionEffects`' existing pattern) — tests that assert their counts must use deltas, not absolute zero, since a still-fading one from an earlier test in the same batch run can legitimately still exist (see `Phase17UxFeedbackTests.ClearFireAndForgetVfx`).
- **Crop selection already existed — verified, not built (2026-07-25).** `World/CropSelection.cs` (Phase 3) tracks a per-region selected crop and `FarmPlot.Interact` plants whatever `CropSelection.SelectedForPlanting` returns for the current region — never a fixed region-default constant. `HudUI`'s "Crop" bottom-bar button (Phase 9) already cycles a region's `CropSelection.OptionsFor` via `CropSelection.Select`. Starlight Vale carries 10 of the 50 crops.json entries, all purchasable. The only real gap was verification: no prior test had planted 2 different crops in the *same* region through the real selector (Phase 3's test proved 2 crops across 2 *different* regions). `Assets/Tests/PlayMode/CropSelectorTests.cs` closes that — real till/plant taps plus a genuine simulated touchscreen tap on the HUD's actual Crop button through `EventSystem`/`InputSystemUIInputModule` (see BUILD_LOG for the `EventSystem` test-isolation bug this surfaced and fixed, scoped to the test only).
- **Animal roles — livestock vs. companions (P3-Phase 18, 2026-07-25).** `World/AnimalRoles.cs` is a code-side table (same pattern as `ExploreTargets`/`NpcSchedule`/`ExclusiveRegionByAnimal`) splitting the 15 animals into **Livestock** (8: chicken, sheep, asteroid_pig, crater_goat, nebula_cow, bee_swarm, butterfly_swarm, firefly_swarm) and **Companions** (7: comet_duck, moon_rabbit, biolume_fox, cosmic_tortoise, glow_axolotl, star_owl, star_slime). **This deliberately disagrees with animals.json's `kind` field in four places** (comet_duck livestock→Companion; the three swarms helper→Livestock) — user-approved. `kind` stays **descriptive** (and still carries the pet-vs-helper distinction the two-way split flattens); `AnimalRole` is **behavioral**. Don't "fix" the mismatch by rewriting `kind`. Companions are the enumerated set, so a new animals.json entry defaults to Livestock rather than silently inheriting a schedule. **The split is behavioral, NOT economic** — companions keep any produce their data defines (star_slime stardust, comet_duck comet_egg), on the unchanged Phase 4b/Phase 8 per-species clock; `AnimalController.Interact` collects produce first for either role, then branches to the companion line. Livestock: bought then placed on **open ground** — `RegionWorldBuilder.IsTillable` (in-bounds + unreserved, the same gate crops use) AND no tilled plot AND no other animal; soil tier is irrelevant to animals. Placement lives in the additive save field `animalPlacements` (`"regionId:animalId"` → `"x,y"`, schema still 2, no migration — empty on old saves falls back to the deterministic paddock spot) and is **per region**, so Phase 4b's one-instance-per-region model is untouched. `AnimalPlacement.Arm()` (from `RanchUI`) + `PlayerController.OnTapWorld`'s armed-state branch are the UX, mirroring Phase 17's tap-to-till. Companions ride Phase 16: `CompanionSchedule` **delegates** stop mapping and the plaza offset to `NpcSchedule` (don't fork that geometry) and treats every companion as `activeAt="any"` since animals.json has no such field; companions stand on their own ring **inside** the human one (`RadiusFactor` 0.9, plaza scatter 1.4 vs 2.5) because a phase offset alone let a companion land 0.16u from an NPC — the Phase 16 stacking bug. Companion wander radius is 0.6 (livestock 2.2): stops are only ~4.4u apart, so a wide wander makes the schedule unreadable. **DATA GAP:** animals.json has no dialogue field at all — a companion's line IS its `notes` prose; the intro/idle split is tracked in `AnimalController._metCompanions` but has nothing distinct to say. Wire `CompanionLine()` if data ever grows a `dialogue` object; don't invent lines.
- **Legibility surfaces (P3-Phase 21, 2026-08-07) — read these before adding any new "show the player X" UI.** Four indicators, all of which read live system state rather than caching or duplicating it. (a) `Farming/CropInfo.cs` is a read-only struct over `crops.json` + `PlotState` exposing stage / total grow time / day-night window; it contains **no crop ids and no literal numbers**. Its `Summary` (one line) and `WorldLines` (stacked) are composed from the same three parts so surfaces can't drift, and `FarmGrid.CropInfoAt(world)` is the accessor (next to `ContextActionAt`, since the grid already owns the world→cell mapping and the `GameState`). `FarmActionPrompt` renders it as a second `TextMesh` **above** the verb — never merge it into the verb mesh, `CurrentLabel` is the contract Phase 17's tests assert. (b) `World/QuestGiverIndicator.cs` shows "!" over quest givers; availability comes from `QuestEngine.StateForGiver`/`CanStartFromGiver`, and **`OnTalkedTo`'s activation loop calls the same `CanStartFromGiver`** — one predicate, so the icon can't advertise a quest talking won't start. Don't reimplement that rule anywhere. (c) `World/ProduceReadyIndicator.cs` shows a sparkle over animals with produce waiting, reading `AnimalController.ProduceReady` so it inherits Phase 8's per-SPECIES clock (collect from one instance → every region's instance goes dark). It **replaces** the old `_body.color * 1.25f` glow, which was a no-op on generated art (white × 1.25 clamps to white); that tint is still in the code for procedural fallback sprites only. (d) Both world icons reuse `InteractionCue.Attach(..., sprite:, name:)` for one shared pulse animation — **note `InteractionCue.Attach` draws `Random.Range` for pulse desync, so attaching one shifts the global `Random` sequence**; that perturbation is what broke a Phase 18 companion test asserting a spawn snap after a frame of randomised wander (fixed by sampling before `Update`, see BUILD_LOG). Both icons use `SetActive`, not `renderer.enabled`, because `NpcController.ApplyTimeOfDay` re-enables every child `Renderer`.
- **"Rewilded" vs "restored" are different mechanics and must stay differently worded (P3-Phase 21).** `FarmState.restoration` = the harvest-driven meter → shown as **"N% rewilded"** (HUD + Star Map). `FarmState.landmarksRestored` = coin-paid landmarks → **"restored"**, with per-landmark `restoreCost`/`unlocks`/done-state listed in the Star Map so a restore is plannable before you find the landmark. **The save field is still named `restoration`** — the rename is display-only, no schema or migration impact. Don't reunify the wording.
- `QuestEngine` is generic — reads `quests.json`, no per-quest code, ever. `GameEvents` is the pub/sub hub connecting farming/NPC/quest systems.
- `SaveManager`: local-first, debounced, schema 2. Save fields are additive-only — new fields are fine, don't restructure existing ones without checking `server/routes/game.js#validateSnapshot` first. World-layout changes that invalidate stored coordinates go through `Save/SaveMigration.cs` (additive `worldVersion` field, applied on SaveManager's load paths and persisted immediately; schema stays 2).
- World geometry (P3-Phase 15, 2026-07-10): regions are **40x40** cells, 80 apart on X (one region-width gap), lush core = cells **12..27** (16x16 = 256 cells; since P3-Phase 17 this is a soil-quality zone, no longer the farmable boundary — the whole 40x40 is tillable), mid ring from edge 6. ALL of it lives in `RegionWorldBuilder` consts (`Size`/`Spacing`/`LushMin`/`LushMax`/`MidMin`) — FarmGrid, decorations, ToolService area checks, `IsTillable`/`ReservedTiles` derive from them; don't hardcode region dimensions anywhere else. Hand-placed offsets that must scale with any future resize: NPC ring radius (`NpcController`), NPC schedule stops (`NpcSchedule` work radius + social plaza offset, P3-Phase 16), animal paddock (`AnimalSpawner`), landmark `Slots`, `ExploreTargets`, QuestEngine's move_to/explore proximity radii, and **camera framing (`CameraFollow.DefaultOrthographicSize`, P3-Phase 20 — the one that already rotted through a resize once)**. Old saves' plot keys migrate +6/+6 once via `SaveMigration` (worldVersion 0 → 1); `hasPlayerPos` is dropped on migration. Visual density for the bigger world is deferred pending the art-direction decision — resize was structural only.
- NPC daily schedules (P3-Phase 16, 2026-07-11): `TimeManager` exposes a 4-period day (`DayPeriod` Morning/Midday/Evening/Night + `OnPeriodChanged`; boundaries derive from `dayStart`/`nightStart`, so periods can't disagree with `IsDay`/`IsNight`). `NpcSchedule` is a code-side table (same pattern as `ExploreTargets` — npcs.json holds no coordinates, don't add them): per period × `activeAt` it picks Home (spawn ring r=14.4), Work (r=9.5, same bearing, just outside the lush core), or Social (shared plaza, center+(0,−11), each NPC scattered on a 2.5 ring around it by its roster bearing — zero spread stacked whole rosters into one sprite, caught in Shay's 2026-07-11 playtest); `NpcController` walks there via `MoveTowards` (`walkSpeed` 1.6), snapping on spawn. Visibility (`ApplyTimeOfDay`) is orthogonal — hidden NPCs still walk. Schedule-aware dialogue is a flagged DATA GAP: dialogue objects only have `intro`/`idle`/`quest_complete`; if data ever grows location keys, wire them in `NpcController.Interact`.
- **Camera framing (P3-Phase 20, 2026-08-07).** `CameraFollow.DefaultOrthographicSize` (**14**) is the single source of truth, consumed by `GameBootstrap.AttachCamera` — never write a bare orthographic size there again. It sat at `7f` from Phase 2's 20x20 era until now; Phase 15's resize to 40x40 updated only the trailing comment, leaving the view showing **6.9%** of a region with no landmark on screen from spawn. 14 is **derived, not taste**: it's the smallest half-height reaching the landmark ring (`LandmarkSpawner.Slots` max +14 on Y) and it brings the NPC home ring (r=14.4) to the frame edge — scale it with those two, not by feel. Legibility budget: art is 64px at PPU 64, so a sprite is 1 world unit and renders at **45.7px** on a 1280px portrait frame (floor 44px, asserted in `Phase20CameraFramingTests`); that is already **0.71x downscaled** under Point filtering, so **don't raise the size further without an art pass**. UI is immune by construction (`UIRoot` is ScreenSpaceOverlay + ScaleWithScreenSize). `CameraFollow.ClampedFocus(focus)` is the one clamp, shared by `LateUpdate` and `SnapTo` — `SnapTo` used to skip it and land outside the region on region travel; don't reintroduce a raw position assignment. At 14 the legal camera box is only 24.3x12.0 inside the 40x40 region, so the clamp actually bites now. **Zoom alone does NOT fix landmark discoverability** — portrait aspect caps halfW at 0.5625*size, so the x=±13 landmarks can't be framed from spawn without pinning the camera; that remainder is a signposting gap (no UI file reads `restoreCost`; the HUD's "% restored" is the unrelated harvest-driven `FarmState.restoration`), not a framing one.
- New Input System only (`activeInputHandler: 1`). Never use `UnityEngine.Input` — it throws.
- Generated sprites (crops + NPCs + animals + ground tiles + landmarks + player): `Tools/art/build-cosmic.mjs` (reused Farm&Give pixel-art library, copied into `Tools/art/`) renders PNGs from crops.json/npcs.json/animals.json/regions.json into `Assets/Resources/Sprites/Generated/`. **Since the Gemini art swap (P3-Phase 9 cont., 2026-07-10) those folders hold curated Gemini art under the same filenames — running the script now REQUIRES explicit category args (`node build-cosmic.mjs player`), and regenerating a category REPLACES its Gemini art with procedural output. Only do that deliberately.** The player sprite (`Player/player.png`) is a procedural stopgap (2026-07-10, no AI Studio credits) — regenerate via Gemini alongside any future art batch. Loaded at runtime via `World.GeneratedSprites` with the old procedural placeholders as automatic fallback. Animals: `ANIMAL_VISUALS` in `build-cosmic.mjs` is a code-side table (animals.json has no body-plan field) mapping each of the 15 animals to a shared body archetype (bird/quad/blob/swarm/amphibian) + one distinguishing marking — same pattern as `AnimalSpawner.ExclusiveRegionByAnimal`. Ground tiles: generated as grayscale texture *masks*, not pre-colored — `RegionWorldBuilder` still tints them via `Tile.color` from `regions.json`'s `groundTiers`, so that stays the single source of truth for per-region color (Unity's tilemap tint multiplies mask pixels against it). Landmarks: `Tools/art/sprites/landmarks.mjs` hand-authors one drawing function per landmark id (7 total, one-off structures — no shared archetype like animals), each with a ruined + restored pair matching `LandmarkController`'s existing `Restored` state, same real-art/fallback pattern as everything else. Effects are still procedural placeholders (no data list drives them, not flagged as a gap).
- Movement animation (P3-Phase 19, 2026-07-25): every character sprite is one static pose (no walk-cycle frames — needs a future Gemini art batch), so `World/MovementAnimator.cs` is a procedural stopgap: bob + squash-stretch driven by the character's own frame-to-frame position delta, shared by `PlayerController` (tap-to-move) and `NpcController` (P3-Phase 16 schedule walking) with neither controller aware it exists. Both `Spawn` methods now parent the `SpriteRenderer` (+ NPC's fallback accent chip) under a child GameObject named `Visual`, and `MovementAnimator` animates *that* transform, never the root — root `transform.position` stays exactly what `MoveStep`/schedule-walking/camera-follow/`interactRange` have always read. **Must call `anim.Init(visual.transform)` right after `AddComponent<MovementAnimator>()`, never assign `.visual` directly** — `AddComponent` runs `Awake`/`OnEnable` synchronously before the next line executes, so anything relying on `OnEnable`-time capture grabs the wrong (root) transform's pose; `Init()` exists specifically to do that capture at the right moment. Code that reaches a player/NPC sprite via `GetComponent<SpriteRenderer>()` on the root needs `GetComponentInChildren<SpriteRenderer>()` instead (`GeneratedArtTests.cs`/`Phase17UxFeedbackTests.cs` already updated); an NPC's placeholder accent chip is at `Visual/Accent`, not `Accent`.

## Verification discipline — do not skip this to save time
- No live Unity MCP dependency for verification. Headless batchmode for compiles:
  `"D:\Unity\6000.5.2f1\6000.5.1f1\Editor\Unity.exe" -batchmode -nographics -projectPath "D:\Unity\Cosmic Bloom" -quit -logFile <path>`
- Unity Test Runner PlayMode tests (headless `-runTests`) for behavior — not manual keypresses, not live Play-mode narration.
- Evidence means an actual file: test XML, a log, a screenshot. Never report something as working without citing the file that proves it.
- The nographics/render test split has a fixed, known-good filter list; pull it from the most recent p*_split_*.xml, don't rebuild it from class names. **Canonical, tracked in git, and deliberately phase-agnostic in name as of 2026-08-07: `Tools/testing/nographics_filter.txt` (103 names, semicolon-joined, BOM-free — PS5.1 `Set-Content -Encoding utf8` writes a BOM that silently breaks the first filter name) + `Tools/testing/render_names.txt` (22 render tests). 125 total as of P3-Phase 21 (2026-08-07).** They were `phase18_*` until P3-Phase 20 renamed them: **bumping the filename every phase is itself a rot mechanism** — the old name lingers, nothing points at it, and drift goes unnoticed. One filename now; git history is the record of change. Don't reintroduce a phase prefix. They lived in `Logs/` until then — which is gitignored, so they were invisible to review, absent from fresh clones, and free to rot unnoticed; that is a root cause of the rot history below, so don't move them back. `Tools/` (not `Assets/`) because Unity never reads them and files under `Assets/` would need committed `.meta` files. Render = anything that calls `Camera.Render()`; putting one in the nographics split is the known render-surface crash. **Always check the list still resolves** — compare the filter's name count against the XML's `total=`; a mismatch means renamed/deleted tests are silently matching nothing.
- **Verify the filters MECHANICALLY whenever tests are added — never by reading them.** Extract every `[Test]`/`[UnityTest]` method from `Assets/Tests/PlayMode/` and diff against the union of both filter files; require **0 missing, 0 dead, 0 duplicates** (125/125 as of P3-Phase 21). A renamed or deleted test still parses fine and just matches nothing, so the run stays exit 0 / all-pass with quietly reduced coverage. **This has now rotted three separate times:** the Phase 9/10 57-name lists dropped Phase8LooseEndTests (restored in phase15); the phase16/17 lists carried two names renamed during Phase 17 plus **never contained any `Phase17*` test at all** (only ad hoc until Phase 18); and **`MovementAnimationTests` (Phase 19, 3 tests, one a `Camera.Render()` screenshot) was in NEITHER list until P3-Phase 21** — its own file header said it belonged in the render split, and nothing checked. Every instance was found by a count/diff, never by eye. Adding tests without running that diff is how this recurs.
- **The two filter files use DIFFERENT separators: `nographics_filter.txt` is semicolon-joined (one line), `render_names.txt` is newline-joined (one name per line). `-testFilter` only accepts `;`** — so the render list must be translated (`tr -s '\r\n' ';'`), never just stripped of newlines. Stripping them glues all names into one unmatchable string and the run reports `total=0`, `result="Passed"`, exit 0: a silent zero-test false pass. That already happened once (2026-07-25) and was caught only by comparing `total=` against the name count. Check that count every run.
- The two 2026-07-05 crash signatures are CLOSED (root-caused P3-Phase 8, 2026-07-09 — see BUILD_LOG): the "DelayedCallManager/coroutine" crash was the render-surface crash misclassified (deterministic repro: any `Camera.Render()` test under `-nographics`; the split already prevents it), and the WorkerManagerASIO exit crash/hang is a Unity-internal asset-import-worker teardown race that fires strictly *after* the results XML is written. Operational rule: if a batchmode process lingers after the results XML exists, force-kill it and trust the XML.
- Before rebuilding any multi-step mechanism (test filters, build scripts, data lookups), check whether a working version already exists from a prior phase and reuse it verbatim instead of re-deriving it. Re-derivation is the pattern behind three separate 2026-07-06 incidents: stale-XML confusion, a rebuilt test filter that crashed Unity twice, and general re-verification overhead.
- Commit to git after every completed unit of work.
- Content/design decisions (anything that changes story, quests, or what the game actually is) — stop and report, don't decide unilaterally, even unattended. Technical/mechanical judgment calls are fine to make and log.

## Decisions already made — don't relitigate these
- Seed economy: auto-buy at `seedPrice` when pouch is empty. No shop UI in scope.
- Sales: instant-sell on harvest, no market UI (matches the old web game).
- Region unlock: coins + level per `regions.json`, NOT a direct restoration threshold. Restoration feeds the economy through quest rewards, not a direct gate.
- Tool tiers: till t3=3×1, water t2=+4 neighbors/t3=3×3, harvest t1=1×2/t2=3×3.
- `GameConfig.CharityEnabled` stays `false`. Don't touch it.
- Animal region distribution (Phase 4b, 2026-07-05 — **replaces** Phase 4's
  one-home-region model, don't build against that old description if you see
  it elsewhere): `animals.json` has no shared/exclusive field —
  `AnimalSpawner.ExclusiveRegionByAnimal` is a code-side lookup table (same
  pattern as `ExploreTargets`) mapping only the **6 region-exclusive** animals
  to their one region; every other animal is **shared** (spawns in all 5
  regions once owned). Exclusives: `glow_axolotl`→Vale, `asteroid_pig`→Sun
  Garden, `crater_goat`→Moon Garden, `star_owl`→Star Garden, `nebula_cow` +
  `star_slime`→Nebula Garden (2 exclusives — confirmed from `regions.json` as
  the region last in progression by both `unlockCoins` (6000) and
  `unlockLevel` (20)). The other 9 animals are shared. See BUILD_LOG.md Phase 4b
  for the full per-animal rationale. `AnimalSpawner.CanSpawnInRegion` is the
  source of truth; `SpawnOwned`/`TryBuy` spawn one instance per eligible
  region. The Phase 4b flagged 5x-income implication is **FIXED (P3-Phase 8,
  2026-07-09)**: the produce clock is per *species*
  (`AnimalController._produceReadyBySpecies`), shared by every spawned

  reschedules species-wide, so income is 1x per owned animal and the
  multi-region instances are pure world ambience. Known gap, not
  fixed: buying an animal only checks `unlockLevel`/coins, not whether its
  exclusive region is unlocked yet — harmless since all 5 regions are always
  built/registered, the animal just waits there.

### UI polish (Phase 6, 2026-07-06)
- Dialogue box no longer overlaps the HUD's bottom button bar (flagged since
  Phase 9, fixed Phase 6) — `DialogueUI`'s panel anchors now sit above
  `HudUI`'s bottom bar's top edge (0.075) with a margin, instead of overlapping it.
- Pattern for any UI panel that renders variable-length real data (not a
  fixed placeholder count): use `Text.resizeTextForBestFit`, not a fixed font

### Open findings from P3-Phase 21 (2026-08-07) — reported, deliberately NOT acted on
- **Tap targeting is exact — "walking paths" is a real feature request, not a workaround.** Verified three ways: `OnTapWorld` resolves plots via `Physics2D.OverlapPoint` (using that plot's own `gridX/gridY`) or `FarmGrid.TryTargetTill` → `WorldToCell`, never the player's position; `ToolService.AreaFor` has no `"plant"` case so plant is exactly 1 cell at any tier; and a test taps 5+ units away and asserts the crop lands on the tapped cell with nothing under the player. Caveat: till t3 / water t2-t3 / harvest t1-t2 **do** have AoE anchored on the tapped cell.
- **Landmark costs are NOT a balance problem.** 900c ≈ 129 harvests of the best crop (starlight_berry, 1.4 c/min/plot); ~40 min at 16 well-watered plots, ~1.5–2.5 h at realistic attention. All three Vale landmarks cost 1550 and refund 580 → **970 net**, against **1425 coins of act-1 quest rewards**. Quest income is the economy; the landmark spreads are a sink balanced against it.
- **Animals are not an income source and shouldn't be balanced as one.** Produce pays `max(2, cost/40)`; every animal's payback is ≥20 h (chicken 20 h, star_slime 81 h), and the clock **does not accrue offline** — `AnimalSpawner.SpawnOwned` calls `ResetProduceClocks()`, zeroing it every session.
- **FLAGGED, needs a design call: `ToolService.EnsureTools` auto-buys unprompted.** Hitting Lv4 then Lv6 silently spends 350c + 500c the next time you till/harvest — 850 coins gone with no UI, competing directly with saving for a 900c landmark, and Lv4 (600 xp ≈ 120 harvests) arrives before most players bank 900. It's the user-approved q_toolsmith mechanism (2026-07-05), so changing it is a content/design decision, not a mechanical one.
- **6 of 50 NPC sprites have an opaque grey checkerboard baked into the PNG** (`helia`, `lull`, `lumina`, `noctua`, `pip`, `pyra`) — the Gemini export wrote the transparency-checker pattern as real pixels. Pre-existing since the Phase 9/10 art swap (visible in `Logs/phase5_sprites.png`). **Don't fix by re-running `build-cosmic.mjs npcs`** — that would replace all 50 Gemini portraits with procedural output. Needs a targeted re-export in a future art batch.

## Token/session hygiene
- Don't run multiple phases of a multi-phase spec in one continuous session — each message resends the full history, so cost compounds fast on long sessions. Finish a phase, commit, and start a fresh session for the next one. `BUILD_LOG.md` and this file are the handoff — not the conversation transcript.
- For read-heavy investigation work (auditing files, evaluating whether something is reusable), delegate to a subagent so the main session's context doesn't fill up with file contents it doesn't need to keep.
- Default to Sonnet 5 for mechanical work. Escalate to Fable 5 only for genuine judgment calls (design tradeoffs, ambiguous requirements, debugging something that resists a first fix).
